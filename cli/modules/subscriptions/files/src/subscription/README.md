## Quick start

| What                               | Where                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| The module                         | `src/subscription/`                                                                   |
| Dependencies                       | `react-native-purchases`, `@gorhom/bottom-sheet`                                      |
| Provider (+ the bottom-sheet host) | `<SubscriptionRoot>` in `src/providers/AppProviders.tsx`                              |
| Paywall screen                     | `/subscription` (Expo Router route file, or a React Navigation root-stack screen)     |
| API keys                           | `EXPO_PUBLIC_REVENUECAT_API_KEY_IOS` / `_ANDROID` in `env.ts` and your `.env.*` files |
| Copy                               | `subscription.*` in every `src/localization/translations/*.json`                      |
| Test mocks                         | `jest.setup.ts`                                                                       |

What is left for you:

| #   | Step                                                                                       | Where                                                                       |
| --- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| 1   | Add your RevenueCat **public SDK keys** (if you skipped the prompt)                        | `.env.development`, `.env.staging`, `.env.production`                       |
| 2   | ⚙ Map your signed-in user to a RevenueCat id                                               | `useSubscriptionUser.ts`                                                    |
| 3   | ⚙ Set the terms / privacy URLs (both stores reject a paywall without them)                 | `config.ts`                                                                 |
| 4   | Create the entitlement named in `config.ts`, attach products, mark an offering **current** | RevenueCat dashboard                                                        |
| 5   | Rebuild the dev client — `react-native-purchases` is native                                | `npx expo prebuild --clean`, then `ios:development` / `android:development` |

Without keys the module stays off: nobody is premium, and the paywall says plans couldn't load. Nothing crashes.

## Gating a feature

```tsx
const { isPremium, requirePremium } = useSubscription();

<Button
  title={t('export.title')}
  onPress={() =>
    requirePremium(startExport, {
      title: t('export.locked_title'),
      description: t('export.locked_body'),
    })
  }
/>;
```

`requirePremium(action, copy)` runs `action` for a subscriber, and otherwise raises the **gate sheet**: your title and description (a user stopped on _export_ is answering a different question from one stopped on _themes_), the offering's feature list, **Try Premium** (opens the paywall) and **Maybe later**.

**Enforce where the value is used, not only where it is chosen.** A setting chosen while subscribed outlives the subscription; check `isPremium` where the premium thing actually happens, not just in the picker that offers it.

To open the paywall from anywhere else: `openPaywall()`.

## Architecture

```
AppProviders
└── <SubscriptionRoot>                 user (useSubscriptionUser) + paywall route (navigation.ts)
    └── <BottomSheetModalProvider>
        └── <SubscriptionProvider>     THE owner: configure, identity, offerings, listener,
            │                          purchase / restore, the one gate sheet
            ├── your navigator
            └── <PremiumGate>          open/closed state lives HERE, not in the provider
                                        (opening the sheet re-renders the sheet, not the app)

  service.ts             the only file importing react-native-purchases
  subscriptionState.ts   PURE: CustomerInfo (+ backend record) → every state
  planChange.ts          PURE: Play replacement modes
  purchaseErrors.ts      PURE: error code → what to tell the user
  statusNotice.ts        PURE: which banner wins
  offeringContent.ts     PURE: offering → paywall plans and features
  introOffer.ts          PURE: formats a real intro offer, invents none
```

- **One listener, one gate.** Only the provider registers a RevenueCat listener and renders the gate, so there is exactly one upsell and it is never out of date.
- **`isPremium` is the live entitlement.** Never cached in another store. Only `ENTITLEMENT_ID` counts — another active entitlement (a second tier, a typo) does not make anyone premium, and logs a dev warning naming what it found.
- **Identity follows your login.** Sign-in calls `logIn`; sign-out calls `logOut`, so the next account starts anonymous instead of inheriting entitlements. The bootstrap is keyed on the user's _id_, so a new `userData` object every render doesn't re-run it.

## Setup

### Keys

RevenueCat → Project settings → API keys → the **public** app-specific keys (`appl_…`, `goog_…`). They are public by design; they still belong in the env files so each environment can point at its own project.

### `config.ts`

| Constant                                  | Meaning                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------- |
| `ENTITLEMENT_ID`                          | The entitlement's identifier in RevenueCat, exactly                       |
| `TERMS_OF_USE_URL` / `PRIVACY_POLICY_URL` | Linked under the purchase button                                          |
| `DEV_ALWAYS_PREMIUM`                      | `true` + `__DEV__` → everyone premium. A test fails if committed enabled. |

### `useSubscriptionUser.ts`

Return `{ id, email?, first_name?, last_name? }` for the signed-in user. `id` must be your backend's stable, non-guessable user id — **never an email**. Until you do, purchases belong to an anonymous id per install: they still work and restore through the store account, but they don't follow the user to a new device by login, and webhooks can't be matched to a user.

## Store configuration that matters

Load-bearing settings — get these wrong and the code can't save you:

1. **Google Play: put all durations in ONE subscription product, as base plans** (`premium:monthly`, `premium:yearly`). Play allows one active purchase per subscription product, so a plan change _replaces_ it. Separate products would let a "change" start a second, concurrently billed subscription.
2. **App Store: put all products in ONE subscription group.** StoreKit resolves upgrades/downgrades within a group; across groups the user is billed twice.
3. **Play's default proration is "charge on next billing date".** That's why `planChange.ts` passes an explicit replacement mode: without it a monthly→yearly _upgrade_ is charged now but doesn't start until the month runs out.
4. **Only advertise trials you sell.** `getTrialText` returns `''` when a product has no real intro offer — and hides one the user is no longer eligible for.
5. **Enable a grace period** on both stores. The module surfaces it as "update your payment method" while access continues — the best moment to save the subscription.

## What the module handles

| Situation                                                           | Behaviour                                                                                                            |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Card failed, store retrying (grace period)                          | Access continues; banner asks to fix payment, links to the store                                                     |
| Play account hold (after grace)                                     | Needs the [backend record](#backend-record-optional); banner says "on hold — don't buy again"                        |
| Cancelled, still inside the paid period                             | Access continues; **Resubscribe** allowed (both stores permit it)                                                    |
| Free trial                                                          | Banner with the trial's end date                                                                                     |
| Play pause                                                          | Banner with the resume date                                                                                          |
| Family Sharing                                                      | Explained; purchasing disabled (it's someone else's)                                                                 |
| Promotional (granted) access                                        | Explained; purchasing disabled                                                                                       |
| Lifetime purchase                                                   | "Lifetime access"; nothing to renew, cancel or switch                                                                |
| Bought on the other store, or on the web (Stripe / RC Web Billing)  | Purchasing blocked **in the provider** (not just the paywall), CTA becomes _Manage_, the store is named              |
| Plan change on Android                                              | Old subscription named via `StoreProductChangeInfo`; upgrade now, downgrade deferred, toast explains delayed changes |
| Plan change refused (subscription belongs to another store account) | Says so and where to change it, instead of reporting success                                                         |
| Two active subscriptions                                            | Warned; points to support                                                                                            |
| Payment pending (cash, Ask to Buy)                                  | "Being processed" — not an error; the listener grants access when it clears                                          |
| Network / store outage                                              | Retryable message                                                                                                    |
| Device restrictions, region, ineligible                             | Final message — no pointless retry                                                                                   |
| Already purchased by this store account                             | Receipts re-synced silently (`syncPurchases`, no sign-in prompt) and access restored                                 |
| Receipt linked to a different app account                           | Explains which account owns it                                                                                       |
| Double tap during a purchase                                        | Ignored                                                                                                              |
| Offerings failed to load                                            | Paywall shows an error with **Try again**                                                                            |
| No API key yet                                                      | Module off, nothing crashes                                                                                          |

## Paywall content from the dashboard

The paywall and the gate read the **current offering**: its packages in the order RevenueCat serves them (weekly … lifetime, all supported), and its **metadata**:

```jsonc
{
  "features": ["Unlimited projects", "Cloud sync", "Priority support"], // or { "en": [...], "es": [...] }
  "popular_package": "$rc_annual", // badge "MOST POPULAR"
  "titles": { "$rc_monthly": { "en": "Pro Monthly", "es": "Pro mensual" } }, // optional per-package titles
}
```

Change bullets, the highlighted plan or titles without an app release. Without metadata, translated defaults are used.

## Backend record (optional)

RevenueCat **cannot** tell the device about two recoverable states:

- **Play account hold** — after grace expires, Play holds a lapsed account up to 30 days. On-device it looks like an ordinary expiry, so without help a recoverable subscriber sees a full paywall and may buy a _second_ subscription.
- **A scheduled downgrade** — the entitlement keeps reporting the old plan until renewal.

If your server keeps a subscription record fed by **RevenueCat webhooks**, pass it as `backendSubscription` in `SubscriptionRoot.tsx` (shape: `BackendActiveSubscription`). It never grants access — the entitlement is still the gate — it only explains a state.

Prefer webhooks over `onPurchaseSuccess` for syncing your backend: they are the only channel that works while the app is closed (renewals, cancellations, refunds), and a client call racing them writes the same rows twice.

## Testing

```bash
yarn test src/subscription
```

The pure modules carry most of the coverage; the provider is tested against a mocked service. The SDK mock in `jest.setup` mirrors the real enum values — a partial mock leaves codes `undefined` and collapses distinct `switch` cases.

On devices: use sandbox accounts (StoreKit sandbox / a Play license tester). A simulator shows offerings but cannot complete a real purchase.
